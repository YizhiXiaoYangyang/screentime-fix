# 探针实测（2026-11-02，v4.0 动手前）

环境：Redmi myron / HyperOS 3.0 / MISettings 16.3.260227.00 / LSPosed(Vector)。
做法：HookEntry 里加编译期常量 `PROBE`，在 `xa.g#b`（列表/详情的数据源）与 `xa.g#c`
（单应用详情入口）的 after 上只打日志，不改数字。装好后在虚拟屏（display 98）打开
「屏幕使用时长统计」，切 日 / 周 / 月 三个 tab 各抓一段。

## 结论

| 要查的 | 实测值 | 对 v4.0 的影响 |
|---|---|---|
| 日视图 `xa.g#b` 返回 | `List<DeviceAppUsage>`，**n=1**，每个元素 `detail` 24 格 | 「每天 +X」= 对每个元素注入 X，日视图直接体现 |
| 周视图 | **n=7**（一天一个元素），每个元素 `detail` 仍是 24 格 | 注入按元素做，周视图自动 = 7 天 × X，不用另算 |
| 月视图 | n≈30（推自 unlock 的 30 格），同为一天一个元素 | 同上 |
| `appDetail` 的 key | **与 `AppUsage.pkgName` 完全相同**（`key=com.maimemo.android.momo pkg=com.maimemo.android.momo`） | 可以直接 `map.put(pkg, new AppUsage(...))` 造条目 |
| `AppUsage.detail` 尺寸 | **24**，与同一元素的 `DeviceAppUsage.detail` 同域 | 注入时按元素 detail 的格子同步写，时间轴才不空 |
| 真实 `categoryId` | `usagestats_app_category_miui_<type>`（字符串资源名），如 `…_miui_education` | 用这个格式，不要直接写 `education` |
| 真实 `categoryType` | `education` / `undefined` / `tools` … 即纯类型名 | 两个字段口径不同，别混 |
| 分类的 key | 也等于 `categoryId` | 分类表 put 用同一个键 |
| `categoryDetail` 大小 | 日视图 10～11 个分类 | 注入时优先挂到已存在的分类，避免新造分类造成「分类数异常」 |
| `xa.g#c` 返回 | **单个 `DeviceAppUsage`**（不是 List），内部两次调 `xa.g#b` | 单 App 详情页的数据就是 b 的结果挑出来的，hook b 即覆盖 |
| 未命中分支 | 返回 `og.a`（`COROUTINE_SUSPENDED`） | 探针判断类型后才计数，别被它占限额（踩过一次） |
| 解锁 `UnlockUsage.unlocks` | 月视图 30 格（每天一个），`unlockTimes=542`，`firstTime=0` | 加解锁次数要按「每天」加，日视图是 24 桶 |

## 顺带确认

- 模块日志**不进 logcat**，写在 `/data/adb/lspd/log/modules_*.log`（tag `VectorLegacyBridge`）。
  以后排查一律 `grep ScreenTimeFix /data/adb/lspd/log/modules_*.log`。
- 模块更新后必须 `am force-stop com.xiaomi.misettings` 再启动，否则设置进程还用旧 dex。
- 只改 `PROBE` 常量不影响行为；探针包与 v3.1 功能等价（已装回 `PROBE=false`）。
- 回退包：`dist/screentime-v3.1-rollback.apk`（54154 B，与装机包同签名 `5585eaac…`）。
- 虚拟屏启动设置要用 `am start --display <id> -a com.xiaomi.misettings.screentime.detail`
  （`launch_app` 会报 `APP_NOT_LAUNCHABLE`，设置是 priv-app）。
