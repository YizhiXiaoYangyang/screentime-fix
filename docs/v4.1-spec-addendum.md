# v4.1 增补契约（时间选择器 + 冲突裁决）

v4.0 已上线并真机验收通过。本次只修三件事，不新增配置键、不改已有键语义。

## 规则（先定死，代码必须照这个）

**R1 同一个 App 既在「单独隐藏」又出现在加成配置里 → 以「藏」为准。**
该 App 不出现、不加时长。UI 必须显式标出这条冲突，禁止静默丢弃。

**R2 总量加成的承载 App 落在隐藏名单里 → 不许丢掉这笔加成。**
- `carrier` 为空（自动）：挑「未隐藏的 App 里 useTime 最大的」；都不可用则用 `Cfg.FAKE_PKG`。
- 用户显式指定了被隐藏的 App：同样顺延到「未隐藏里最活跃」，并记一条日志；UI 上把该行标红提示。
- 只有 `loadConfig` 的加成日志允许每进程打一次提示，不许刷屏。

**R3 加成的落点不得进入「整小时被隐藏」的桶。**
- 权重优先用该 App「裁后」的 detail（v4.0 行为，保持）。
- 裁后权重全 0 时：不要直接均匀撒 24 个小时，而是用「未被隐藏的小时」当权重（一小时被 `Cfg.coveredMinutes(...) >= 60` 视为被隐藏）。
- 极端情况：全天 24 小时都被隐藏 → 退回 8:00–23:00 均匀（不要抛异常，也不要落到凌晨）。

**R4 加成时段与隐藏时段重叠 → 重叠部分不落点**，其余照旧；UI 给一句提示。

**R5 每日上限不管加成**（v4.0 已定，本次不动）。

## A：Cfg（只加，不改既有）

```java
/** 两组窗口在一天内是否有任何重叠（并集语义，支持跨零点）。空了返回 false。 */
public static boolean windowsOverlap(java.util.List<int[]> a, java.util.List<int[]> b);

/** 一天里「整小时被窗口完全覆盖」的小时数（0..24）。 */
public static int fullyCoveredHours(java.util.List<int[]> wins);
```

CoreTest 追加用例：空/null、单边为空、相接不算重叠（`30-60` 与 `60-90`）、真重叠、跨零点对跨零点、`coveredMinutes >= 60` 的边界、`fullyCoveredHours` 全天/半天/零。

不要动 `Store`、不要动 v4.0 已定的任何函数。

## B：HookEntry（只改注入侧）

1. `planIncrements(...)`：
   - 新增「排除隐藏 App 后挑最活跃」的逻辑（`heaviestPkg(apps, exclude)`），`carrier` 为空或指定值被隐藏时都用它。
   - 找不到任何可用 App → 用 `Cfg.FAKE_PKG`。
   - 单个 App 加成命中隐藏名单 → 跳过（R1），并打一条限流日志（每进程最多 3 条，内容含包名）。
2. `distribution(...)`（或等价方法）：
   - 现有权重路径不变（用裁后 detail）。
   - 权重全 0 时按 R3 生成「未被隐藏小时」的权重（用 `sWindows` + `Cfg.coveredMinutes`，整小时被覆盖 = 权重 0，其余 = 1），再走 `Cfg.distribute`。
   - 全天被藏（可用小时为 0）→ 用 8:00–23:00 等权。
   - 桶数不是 24 时（理论上不会发生，detail 恒 24）→ 退回均匀。
3. 不改 `trimUnlockUsage` 的既有语义（解锁仍按裁后分布加，天然满足 R3）。
4. 任何新增异常都必须吞掉，退回 v4.0 的行为，不能让现有「藏」变差。

自测：`javac … $(find src -name '*.java')` 必须 0 error（其余同事的改动可能同时在树里，报别人的缺符号属预期，报你自己的必须修）。

## C：AddActivity（界面）

1. **加成时段改成时间选择器**，照 `MainActivity` 的 `rebuildList() / buildRow(idx) / pick(idx,isStart)` 那套复制过来：
   - 每行：`Ui.TimeChip` 开始 → `Ui.TimeChip` 结束 + 右侧时长文字（`durText`）+ `Ui.CloseButton` 删除（34dp）
   - 底部「＋ 添加时段」；为空时显示「没有时段（按真实活跃分布）」
   - 点时间块弹 `TimePickerDialog`（`dlgTheme()` 同款主题），选完立即刷新行与 `Ui.Timeline`
   - 内部仍存 `List<int[]>`（第几分钟），保存时 `Cfg.join(...)`；**界面上一个数字都不出现**
2. **承载 App 可清除**：选中后右侧出现 `×`（`Ui.CloseButton`，34dp），点了 → `mCarrier = ""`，行恢复「自动（用得最多的 App）」。长按也走同一逻辑（可选）。
3. **冲突提示**（R1/R2/R4）：
   - 「单独加的 App」里若有包在隐藏名单 → 该行数字旁加一行小字「与「单独隐藏的 App」冲突，以隐藏为准」，颜色用 `Ui.accent(this)`
   - 承载 App 若在隐藏名单 → 承载行下方提示「这个 App 在隐藏名单里，会改用未隐藏里最活跃的」
   - 加成时段与隐藏时段有重叠（`Cfg.windowsOverlap(addWins, hideWins)`）→ 时段区下方提示「与隐藏时段有重叠，重叠部分不会加点」
   - 隐藏名单与隐藏时段从哪里读：`Store.load(this)` 返回的 `Snapshot.hideApps` / `Snapshot.windows`
4. 保存逻辑、键名、`Store.saveAdd(...)` 调用方式不变；`mWindows` 变量名若与既有冲突（AddActivity 里已有一个表示「加成时段」的字段），自行改名，别动 `MainActivity`。

自测：`javac --release 8 …` 0 error（容忍别人的缺符号）；不要跑 `build.sh`。
